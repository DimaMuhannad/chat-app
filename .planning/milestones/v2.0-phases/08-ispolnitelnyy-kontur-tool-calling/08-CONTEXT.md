# Phase 8: Исполнительный инструментальный контур (Tool Calling) - Context

**Gathered:** 2026-10-05
**Status:** Ready for planning

<domain>
## Phase Boundary

Создание полноценного исполнительного контура ассистента через Function Calling (Google GenAI SDK `types.Tool`) в `SecretaryDialogEngine`. Устранение иллюзии выполнения действий («галлюцинаций») при обработке запросов на планирование (Google Calendar, локальные напоминания, черновики писем). 

Строгий HITL-шлюз гарантирует, что любое физическое действие (создание события, запись напоминания в БД, подготовка черновика) выполняется только после явного нажатия кнопки подтверждения владельцем в Telegram. Поддержка двухшагового Tool Calling для контекстного поиска информации в письмах («из письма Новиковой») и уточняющих вопросов при неполных датах.

В рамках фазы:
- Регистрация декларативных схем инструментов в `SecretaryDialogEngine` (`create_calendar_event`, `create_reminder`, `draft_email_reply`, `search_emails`).
- Строгая антигаллюцинационная директива в системном промпте секретаря.
- Формирование интерактивных HITL-карточек в Telegram с инлайн-кнопками `[Подтвердить]` и `[Отмена]`.
- Уточняющий диалоговый сценарий при отсутствии времени события/дедлайна.
- Локальный буфер в SQLite (`pending_sync`) для гарантированной доставки при сетевых сбоях Google Calendar API.
- Специализированные интенты планирования в `FastIntentRouter`.

Вне рамок фазы:
- Автоматическая отправка писем адресатам (только сохранение черновика).
- Прямое удаление календарей или массовая очистка событий.
- Подключение новых сторонних мессенджеров (это инициатива `RUS-LOC`).
</domain>

<decisions>
## Implementation Decisions

### 1. Политика подтверждения (HITL Guardrail)
- **D-01:** Строгий HITL для всех исполнительных действий. Бот никогда не записывает событие в Google Calendar, не создает напоминание и не сохраняет черновик письма напрямую из текста пользователя — он обязан сформировать интерактивную Telegram-карточку с деталями и инлайн-кнопками `[✅ Подтвердить]` / `[❌ Отмена]`. Физическая запись происходит ТОЛЬКО по `callback_query`. — **Reversibility:** costly — определяет архитектуру обработчиков колбэков и схему транзакций.

### 2. Контекстный поиск по письмам и данным
- **D-02:** Двухшаговый Tool Calling. При запросе пользователя, ссылающемся на внешнюю переписку («добавь дату из письма Новиковой»), модель первым шагом вызывает `search_emails(sender="Новикова")`, получает структурированный сниппет подходящих писем, и вторым шагом извлекает точную дату и формулирует параметры создания события/напоминания. — **Reversibility:** reversible.

### 3. Обработка неполных данных
- **D-03:** При отсутствии точного времени события (например, «событие в пятницу» или «дедлайн 12 октября») бот обязан задать короткий уточняющий вопрос пользователю («В какое время запланировать?»), а не подставлять произвольные дефолтные часы. — **Reversibility:** reversible.

### 4. Отказоустойчивость Google Calendar API
- **D-04:** Локальный буфер в SQLite (`pending_sync`). Если Google Calendar API недоступен или возвращает сетевую ошибку / истекший токен при подтверждении HITL-карточки, задача сохраняется локально в базу данных со статусом `pending_sync`, а пользователю выводится уведомление с кнопкой `[🔄 Повторить синхронизацию]`. — **Reversibility:** costly — требует добавления поля статуса синхронизации в схему событий.

### 5. Антигаллюцинационный промпт
- **D-05:** В системный промпт `SecretaryDialogEngine` вшивается категорический запрет утверждать об исполнении действий без предварительного вызова инструмента и получения подтверждения. — **Reversibility:** reversible.

### Claude's Discretion
- Точные типы и названия полей в JSON-схемах `types.Tool`.
- Визуальный дизайн карточки подтверждения в Telegram (эмодзи, форматирование дат через `datetime.strftime`).
- Формат временного токена подтверждения в `callback_data` (payload HITL-запроса).

</decisions>
