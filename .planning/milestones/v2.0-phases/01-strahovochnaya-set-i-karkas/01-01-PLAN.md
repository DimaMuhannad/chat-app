Константы: `CHAT_DIR = Path(__file__).resolve().parents[1]`; `CORE_DIR = Path(os.environ.get("ASSISTANT_CORE_DIR", "/opt/assistant-core"))` (D-01); `LIVE_DB = CORE_DIR / "data" / "assistant.db"`; `CHAT_VENV_BIN = CHAT_DIR / "backend" / ".venv" / "bin"`; `CORE_VENV_BIN = CORE_DIR / ".venv" / "bin"`; `PYTEST_TIMEOUT_S = 900`.

3. `sha256_file(path: Path) -> str` — hashlib.sha256, чтение блоками.
4. `make_db_copy(live_db: Path, tmp_dir: Path) -> Path` — консистентная копия через `sqlite3.connect(live_db.as_uri() + "?mode=ro", uri=True)` и метод `backup()` в `tmp_dir / "assistant-copy.db"`; оба соединения закрываются в finally; не shutil.copy. 5. `run_cmd(cmd: list[str], cwd: Path, env_extra: dict[str, str] | None = None, timeout: int = PYTEST_TIMEOUT_S) -> subprocess.CompletedProcess` — всегда список аргументов, `shell=False`, `capture_output=True`, `text=True`; окружение = копия os.environ, дополненная env_extra.
6. `chat_pytest_env(db_copy: Path | None) -> dict[str, str]` — возвращает словарь с единственным ключом `SQLITE_DB_PATH` = str(db_copy); бросает ValueError, если db_copy равен None или `db_copy.resolve() == LIVE_DB.resolve()`. Причина: CRUD-тесты chat-app пишут в БД, без копии pytest chat-app не запускается никогда.
7. `pytest_counts(junit_xml: Path) -> dict[str, int]` — ключи tests, failures, errors, skipped из элемента testsuite (корень может быть testsuites или testsuite); `failed_test_ids(junit_xml: Path, limit: int = 10) -> list[str]` — «classname::name» для testcase с дочерним failure или error.
8. `pytest_summary_flags(output: str) -> list[str]` — взять последнюю итоговую строку pytest (последняя строка, начинающаяся с «=» и содержащая « in ») и вернуть найденные в ней слова из множества {failed, error, errors, skipped, deselected, xfailed, xpassed} (D-02: скрытых deselect/skip/xfail нет).
9. `pytest_ok(returncode: int, counts: dict[str, int], flags: list[str]) -> bool` — True только при returncode == 0, tests > 0, failures == errors == skipped == 0 и пустом flags (код 5 «ничего не собрано» — красный).
10. `run_pytest_step(repo: str, pytest_bin: Path, target: str, cwd: Path, env_extra: dict[str, str] | None, tmp_dir: Path, save_dir: Path | None) -> CheckResult` — команда: str(pytest_bin), target, "-v", "-p", "no:cacheprovider", f"--junitxml={tmp_dir}/junit-{repo}.xml", f"--basetemp={tmp_dir}/pytest-{repo}". Имя строки — «pytest — тестов: N». Нет файла pytest_bin → ✗ «не найден pytest: путь»; таймаут → ✗ «превышено время»; при ✗ detail = итоговая строка pytest и до 10 id упавших тестов (не весь вывод). 13. `render_report(results: list[CheckResult]) -> str` — по-русски: заголовок «Гейт качества», колонки «Репозиторий», «Проверка», «Результат», значок ✓ или ✗, для ✗ под строкой деталь с отступом и префиксом «↳»; последняя строка ровно «ИТОГ: ЗЕЛЁНЫЙ» или «ИТОГ: КРАСНЫЙ» (D-02).
