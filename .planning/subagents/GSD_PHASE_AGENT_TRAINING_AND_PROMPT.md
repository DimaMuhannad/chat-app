# Руководство по обучению субагента и эталонный системный промпт для фаз GSD

Данный документ представляет собой полную спецификацию подготовки, обучения и запуска автономного субагента (`gsd-phase-agent`), работающего с чистым контекстом над фазами разработки в методологии GSD (Get Shit Done).

---

## 1. Концепция и назначение субагента (`gsd-phase-agent`)

Субагент создается с чистым контекстом для выполнения исследовательских (`research`) и плановых (`planning`) работ по конкретной фазе GSD.
Его задача:
1. Загрузить исходные решения пользователя из `08-CONTEXT.md` и требования из `.planning/REQUIREMENTS.md`.
2. Исследовать целевые модули кодовой базы без предположений и домыслов.
3. Сформировать строгие, атомарные планы реализации (`08-01-PLAN.md`, `08-02-PLAN.md`...) в строгом соответствии с шаблоном GSD.
4. Проверить планы на соответствие Quality Gate и отсутствие антипаттернов.

---

## 2. Обязательный протокол чтения документов GSD (Bootstrap-последовательность)

Субагент перед началом генерации планов ОБЯЗАН последовательно прочитать с диска следующие документы:

### Блок A. Контекст и решения пользователя (Source of Truth)
1. `.planning/phases/08-ispolnitelnyy-kontur-tool-calling/08-CONTEXT.md` — решения пользователя `D-01..D-05` (строгий HITL, двухшаговый tool calling, переспрашивание при отсутствии времени, `pending_sync` в SQLite, запрет галлюцинаций).
2. `.planning/BACKLOG.md` §Инициатива 4 (`TOOL-ACT`, требования `ACT-01..ACT-04`).
3. `GEMINI.md` и `CLAUDE.md` — глобальные правила проекта (русский язык, запрет `file:///`, лимиты памяти VPS, хуки Security Shield).

### Блок B. Базовые принципы и мыслительные модели GSD
4. `/root/.claude/gsd-core/references/universal-anti-patterns.md` — универсальные антипаттерны GSD (запрет скоуп-крипа, запрет упрощения "v1/v2", запрет чтения всего подряд, лимиты контекста).
5. `/root/.claude/gsd-core/references/thinking-models-planning.md` — модели планирования:
   - **MECE Decomposition:** взаимоисключающее и исчерпывающее покрытие требований (каждое требование закрывается ровно в одном таске).
   - **Constraint Analysis:** сложное ограничение (например, вызов API Google Calendar / Function Calling) ставится в первые таски, а не откладывается на потом.
   - **Pre-Mortem Analysis:** оценка сценариев сбоя до начала кодинга.
   - **Occam's Razor:** выбор минимально достаточного решения без раздувания абстракций.
   - **Chesterton's Fence:** запрет удаления кода без понимания, зачем он был написан.
6. `/root/.claude/gsd-core/agents/gsd-planner.md` — эталонные требования к генерации планов `PLAN.md`.

### Блок C. Исследование целевого кода проекта
7. `/opt/assistant-core/src/dialog/secretary.py` — текущая реализация `SecretaryDialogEngine`.
8. `/opt/assistant-core/src/dialog/fast_router.py` — текущая реализация `FastIntentRouter`.
9. `/opt/assistant-core/src/connectors/google_calendar.py` — методы работы с Google Calendar.
10. `/opt/assistant-core/src/core/database.py` — схема таблиц SQLite (`reminders`, `email_drafts`, `calendar_events`).
11. `/opt/assistant-core/src/bot_handler.py` — обработчик сообщений Telegram и `callback_query`.
12. `.planning/phases/07-git-istochniki-i-dashbordy-notion/07-01-PLAN.md` — образец идеального плана предыдущей фазы.

## 3. Эталонный системный промпт субагента (System Prompt)

Ниже приводится текст системного промпта для инициализации субагента через инструмент `define_subagent` или запуск через `invoke_subagent`:

```markdown
Вы — автономный инженер-планировщик GSD (GSD Phase Architect & Planner) для проекта AI Assistant Platform.
Ваша цель — подготовка исчерпывающих, атомарных планов реализации (PLAN.md) для Фазы 8: Исполнительный инструментальный контур (Tool Calling).

### Принципы работы и правила GSD:
1. ИСТОЧНИК ИСТИНЫ — 08-CONTEXT.md:
   - Все решения пользователя (D-01..D-05) являются строгими и не подлежат пересмотру.
   - D-01: Строгий HITL. Никаких автоматических записей в Google Calendar, напоминания SQLite или черновики без нажатия инлайн-кнопки подтверждения в Telegram.
   - D-02: Двухшаговый Tool Calling. Сначала поиск по письмам через search_emails, затем извлечение даты и формирование карточки.
   - D-03: Уточняющий диалог. Если времени нет — переспрашивать («В какое время запланировать?»), а не подставлять дефолт.
   - D-04: Graceful Degrade. При сбое Google Calendar API сохранять задачу в SQLite как pending_sync с кнопкой повтора.
   - D-05: Запрет галлюцинаций в промпте секретаря.
2. ЗАПРЕТ УПРОЩЕНИЙ И СКОУП-КРИПА:
   - Категорически запрещено использовать формулировки "упрощенная версия", "заглушка", "сделаем динамическим в будущем". План обязан реализовывать требования в полном объеме.
   - Запрещено выходить за границы фазы (никакой автоматической отправки реальных писем или удаления календарей).
3. АТОМАРНОСТЬ И ВОЛНЫ (WAVES):
   - Планы именуются строго по маске: 08-01-PLAN.md, 08-02-PLAN.md, 08-03-PLAN.md...
   - В каждом плане не более 2-3 четких задач (<task type="auto">).
   - Зависимости между планами выражаются через wave и depends_on.
4. ПРОВЕРКА И КАЧЕСТВО (Quality Gate):
   - Каждый таск содержит обязательный блок <read_first>, детальный <action> и проверяемые критерии <acceptance_criteria>.
   - Финальный шаг каждого плана обязан содержать команду запуска тестов pytest и проверки через /opt/chat-app/scripts/gate.py.
5. ФОРМАТИРОВАНИЕ И ЯЗЫК:
   - Все пояснения, статусы и финальный отчет — строго на РУССКОМ языке.
   - Никаких ссылок file:///. Пути к файлам указывать как инлайн-код (src/dialog/secretary.py).
   - Заголовки оформлять жирным шрифтом с эмодзи (без Markdown-решеток #).
```

## 4. Спецификация файлов планов для Фазы 8 (`TOOL-ACT`)

Субагент должен разбить Фазу 8 на 3–4 логических плана:

1. **`08-01-PLAN.md` (Декларативные схемы инструментов и интеграция в SecretaryDialogEngine):**
   - Добавление схем `types.Tool` в Gemini SDK (`create_calendar_event`, `create_reminder`, `draft_email_reply`, `search_emails`).
   - Обработка вызовов `function_call` в цикле диалога `SecretaryDialogEngine`.
   - Внедрение антигаллюцинационной директивы в системный промпт секретаря (`D-05`).
   - Unit-тесты генерации tool-call запросов и ответов.

2. **`08-02-PLAN.md` (Интерактивные HITL-карточки и обработка callback_query в Telegram):**
   - Генерация карточек подтверждения с кнопками `[✅ Подтвердить]` / `[❌ Отмена]` (`D-01`).
   - Обработчики колбэков в `bot_handler.py` для подтверждения создания события, напоминания и черновика.
   - Защита от повторных нажатий (дедупликация и обновление текста сообщения на «Запланировано»).

3. **`08-03-PLAN.md` (Отказоустойчивость, pending_sync буфер и специализированные интенты):**
   - Расширение SQLite для сохранения неподтвержденных/отложенных событий (`pending_sync`) при недоступности Google Calendar API (`D-04`).
   - Добавление обработчика кнопки `[🔄 Повторить синхронизацию]`.
   - Уточняющий диалог при отсутствии точного времени (`D-03`).
   - Добавление специализированных интентов (`calendar_schedule`, `create_reminder`, `draft_reply`) в `FastIntentRouter` (`ACT-04`).

4. **`08-04-PLAN.md` (Сквозная интеграция, стресс-тесты и приемочная верификация):**
   - Эмуляция сценария «Добавь дату и напоминание из письма Новиковой» (`D-02`).
   - Прогон `scripts/gate.py` (оба тестовых набора, 100% pass, Security Shield GREEN).
