## Стратегический бэклог (следующие циклы)

Подробная спецификация требований зафиксирована в `.planning/BACKLOG.md`:
1. **Импортозамещение и РФ-сервисы (`RUS-LOC`, LOC-01..LOC-04):** аудит зарубежных привязок, альтернативы LLM (YandexGPT/GigaChat/vLLM/Ollama), отечественные облака, исследование API мессенджеров Max и VK, абстракция `BaseMessengerAdapter`.
2. **Обучение `chat-app` стандарту GSD и мультиагентность (`GSD-AGENT`, GSD-01..GSD-05):** автономный GSD-регламент, фоновые инженерные субагенты, неблокирующий диалог в чате, интерактивный опрос с кнопками/мультивыбором, динамический закрепленный статус-бар (Live HUD).
3. **Умный онбординг и интерактивные коннекторы (`ONB-CON`, ONB-01..ONB-05):** интерактивный мастер первого запуска, подключение/отключение коннекторов в диалоге, кастомизация плашек, проактивный секретарь, поступательное раскрытие возможностей (Progressive Disclosure).
4. **Исполнительный инструментальный контур ассистента (`TOOL-ACT`, ACT-01..ACT-04):** Function Calling в `SecretaryDialogEngine` (Google Calendar, Reminders, Email Drafts), защита от галлюцинаций в промптах, интерактивные HITL-карточки подтверждения действий, целевые интенты в `FastIntentRouter`.
5. **Интерфейс взаимодействия, динамические команды и аудит качества (`BOT-UXQ`, UXQ-01..UXQ-04):** динамическое меню команд при подключении сервисов (`set_my_commands`), декларативное управление алиасами и видимостью, контекстно-зависимые клавиатуры (Quick Replies), точки роста качества (наблюдаемость, задержки < 250 мс, Mobile-First эргономика).
6. **Динамические специализированные субагенты и семантическая оркестрация (`SPEC-AGENTS`, SUB-01..SUB-05):** 4-компонентная капсула субагента (замороженный контекст, база знаний, папка документов, раздел памяти в SQLite), двухуровневый семантический роутер запросов, паттерны Supervisor Tool Use vs Thread Handoff, декларативный реестр и дообучение в чате.




## Операционные пункты (не фазы)

Фиксируются для учёта; не входят в покрытие требований. Подробности — `.planning/REQUIREMENTS.md`, раздел «Операционные пункты».

- **OPS-01**: `/usr/local/bin/systemctl` молча подделывает успешные `stop`/`restart` для dev-bridge (печатает «active», код 0). Реальное состояние проверять через `systemctl is-active`.
- **OPS-02**: ключ API в открытом виде в systemd-юните dev-bridge (файл читается всеми локальными пользователями). Решение владельца: НЕ ротировать; экспозиция только зафиксирована.
- **OPS-03**: assistant-worker не завершается по SIGTERM и добивается SIGKILL; WAL (Фаза 4) снижает риск порчи БД, но не устраняет его.
- **OPS-04**: сломанный импорт в chat-app-копии `scripts/notion_dev.py` — отдельная мелкая задача вне миграции (W7).
- **OPS-05**: Web API без аутентификации и CORS `*` — v2 (AUTH2-01/02); решить до разморозки chat-app.
- **OPS-06**: состояние «заморожен»; разморозка — решение владельца, не шаг фазы.
