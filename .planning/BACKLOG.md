# Бэклог стратегического развития платформы (Milestone v2.0+)

Документ фиксирует перспективные инициативы, декомпозированные на требования и архитектурные блоки для последующей реализации.

---

## 🇷🇺 Инициатива 1: Импортозамещение, суверенизация и исследование РФ-сервисов (`RUS-LOC`)

**Цель:** Полная независимость от зарубежной серверной инфраструктуры, устранение рисков блокировок внешних API, адаптация к российскому стеку сервисов и корпоративным мессенджерам.

### Требования:
- **`LOC-01` (Аудит внешних зависимостей платформы):**
  - Инвентаризация всех сетевых вызовов за пределы РФ: Google Gemini API (`google-genai`), Google Calendar API, Google Drive API, Notion API v1, внешние IMAP/SMTP серверы, VPS-хостинг.
  - Формирование матрицы рисков доступности и комплаенса (152-ФЗ, требования к критической информационной инфраструктуре).

- **`LOC-02` (Исследование и адаптация отечественных LLM / Self-Hosted инференса):**
  - Оценка качества, стоимости и задержек российских языковых моделей: **YandexGPT** (Yandex Cloud Foundation Models API), **GigaChat** (Сбер API).
  - Исследование и интеграция локальных рантаймов без отправки данных в облака: **vLLM** / **Ollama** с открытыми моделями (Qwen 2.5 / DeepSeek R1 / Llama 3) на выделенных серверах.
  - Проектирование абстрактного порта `BaseLLMProvider` для прозрачного переключения между Gemini, YandexGPT, GigaChat и Ollama.

- **`LOC-03` (Отечественные аналоги облачных хранилищ и дашбордов):**
  - Замена Google Calendar ➔ Яндекс Календарь (CalDAV / API).
  - Замена Google Drive ➔ Яндекс Диск API / VK WorkSpace Облако / локальный S3-совместимый MinIO.
  - Замена Notion Second Brain ➔ исследование отечественных трекеров и баз знаний: **Kaiten**, **Weeek**, **Teamly**, **Yandex Tracker** или локальное хранилище на базе SQLite + Markdown (Obsidian-совместимый контур).

- **`LOC-04` (Отвязка от Telegram: исследование мессенджеров Max и VK):**
  - **Мессенджер Max (ведомственный / корпоративный):**
    * Исследование доступности Bot API / Webhook API мессенджера Max.
    * Оценка поддержки интерактивных элементов: инлайн-кнопки, callback query, отправка форматированного текста, прикрепление файлов.
    * Анализ ограничений скорости (rate limits) и протокола авторизации.
  - **Экосистема VK (VK Teams / VK Мессенджер / VK Bot API):**
    * Исследование VK Teams Bot API (корпоративный контур) и VK Community Bot API.
    * Проверка поддержки: клавиатуры (inline/keyboard), карусели, редактирование сообщений (для динамического табло / Live Ticker), обработка голосовых сообщений.
  - **Архитектурная отвязка (`BaseMessengerAdapter`):**
    * Вынос Telegram-специфичного кода `bot_handler.py` в обобщенный порт `BaseMessengerAdapter`.
    * Реализация модульных адаптеров: `TelegramAdapter`, `VkMessengerAdapter`, `MaxMessengerAdapter`.
    * Поддержка параллельной работы нескольких мессенджеров для одного пользователя.

## 🤖 Инициатива 2: Обучение `chat-app.service` стандарту разработки GSD и мультиагентная оркестрация (`GSD-AGENT`)

**Цель:** Превращение Antigravity Web Studio (`chat-app`) в полноценную автономную агентную IDE, способную по входящей задаче вести канонический цикл разработки GSD, общаясь с пользователем через интерактивные диалоги и делегируя код субагентам.

### Требования:
- **`GSD-01` (Обучение chat-app стандарту разработки GSD):**
  - Интеграция канонического регламента GSD в ядро `chat-app`:
    * Этап 1: Сбор контекста и выявление серых зон (`CONTEXT.md`, `DISCUSSION-LOG.md`).
    * Этап 2: Исследование кодовой базы и проверка гипотез (`RESEARCH.md`, `VALIDATION.md`).
    * Этап 3: Декомпозиция на волны и атомарные планы (`PLAN.md`).
    * Этап 4: Пошаговое исполнение с проверкой Quality Gate (`SUMMARY.md`).
  - Системный промпт оркестратора `chat-app` наделяется строгими правилами следования процессу GSD без «срезания углов».

- **`GSD-02` (Фоновые инженерные субагенты):**
  - Архитектура разделения ролей: основной чат-ассистент управляет высокоуровневым диалогом, а задачи реализации делегирует изолированным фоновым субагентам (`code-writer`, `test-runner`, `git-operator`, `doc-syncer`).
  - Выделенные изолированные сессии (git worktrees или каталоги в `scratch/`) для каждого субагента, исключающие порчу основного дерева кода до подтверждения.

- **`GSD-03` (Неблокирующий диалог в чате):**
  - Пользовательский сеанс чата не зависает на время компиляции, запуска тестов или прогона долгих скриптов.
  - Ассистент продолжает отвечать на вопросы пользователя параллельно с выполнением инженерной задачи субагентами.

- **`GSD-04` (Интерактивный диалог и структурированный опрос):**
  - Механизм отправки вопросов пользователю в веб-чат с готовыми вариантами ответов:
    * Кликабельные кнопки вариантов (вариант 1, вариант 2, вариант 3).
    * Поддержка мультивыбора (выбор нескольких опций кликом или прямым вводом номеров через запятую: `1, 3`).
    * Текстовое поле для ввода собственного уточнения (write-in option).

- **`GSD-05` (Динамический статус-бар задачи / Pinned Progress):**
  - Визуальный закрепленный виджет (status bar / live HUD) в интерфейсе чата:
    * Текущая фаза, номер волны и плана (например: `Фаза 8 [План 08-02] • Волны: 2/3 • Прогресс: 65%`).
    * Статус фоновых субагентов (иконка активности, имя выполняемой операции).
    * Ссылка на формируемые артефакты и diff изменений.

## 🌟 Инициатива 3: Умный онбординг, интерактивное подключение коннекторов и персонализация `assistant-worker.service` (`ONB-CON`)

**Цель:** Максимально плавный и дружелюбный пользовательский опыт для новых пользователей персонального ассистента без необходимости ручного редактирования конфигурационных файлов.

### Требования:
- **`ONB-01` (Интерактивный онбординг-мастер — Welcome Flow):**
  - При первом подключении пользователя (в Telegram / Web / VK / Max) ассистент запускает интерактивный пошаговый мастер настройки.
  - Опрос пользователя о его роли (преподаватель, исследователь, разработчик, менеджер), организации, предпочтительном графике и базовых рабочих пространствах.
  - Автоматическая генерация начальной конфигурации `persona.yaml` на основе ответов пользователя.

- **`ONB-02` (Интерактивное управление коннекторами в диалоге):**
  - Возможность в любой момент написать ассистенту: *«Подключи новую почту»*, *«Добавь сайт расписания»*, *«Отключи LMS»*.
  - Ассистент в интерактивном режиме:
    * Проверяет, поддерживает ли текущая версия требуемый тип коннектора.
    * Пошагово запрашивает необходимые параметры (адрес сервера, логин, токен, расписание опроса).
    * Выполняет безопасный `health_check` соединения.
    * Активирует коннектор и регистрирует привязку в базе данных без перезагрузки всего сервиса.

- **`ONB-03` (Кастомизация плашек и стандартных уведомлений):**
  - Настройка формата, состава блоков и расписания отправки регулярных сообщений через диалог:
    * Утренний брифинг (время отправки, включение/выключение блоков погоды, почты, расписания, табеля).
    * Вечерний дайджест (формат рефлексии, учет задач, выжимка дня).
    * Настройка плашек безопасности (Security Tiles): отображение уровней допуска, предупреждений о компрометации.

- **`ONB-04` (Проактивный секретарь с рекомендациями новых фич):**
  - Ассистент действует как заботливый исполнительный помощник:
    * Замечает сценарии использования и делает контекстные предложения: *«Вы часто просматриваете почту от кафедры в 18:00. Хотите, я буду готовить сводку к этому времени?»*.
    * При обновлении платформы отправляет ненавязчивое объяснение новых возможностей простым человеческим языком.
    * Запрашивает обратную связь: *«Удобен ли вам такой формат карточки задачи?»*.

- **`ONB-05` (Поступательное раскрытие возможностей — Progressive Disclosure):**
  - Принцип защиты новичка от когнитивной перегрузки:
    * День 1–3: базовые сценарии (заметки, быстрые напоминания, список задач, расписание).
    * День 4–7: почтовый щит, брифинги, синхронизация с календарем.
    * Неделя 2+: профессиональные инструменты (HITL-шлюз, табели, LMS, Git-мониторинг, Notion Second Brain).
  - Пользователь видит новые разделы интерфейса и команды по мере освоения предыдущих.

## 🛠️ Инициатива 4: Исполнительный инструментальный контур ассистента (Tool Calling & Real Actions — `TOOL-ACT`)

**Цель:** Устранение галлюцинаций исполнения при диалоге с секретарем. Предоставление языковой модели реальных инструментов (Function Calling) для физического воздействия на окружение (создание событий Google Calendar, добавление напоминаний в SQLite, подготовка черновиков писем) с подтверждением через Human-in-the-Loop.

### Требования:
- **`ACT-01` (Function Calling в SecretaryDialogEngine):**
  - Описание схем инструментов (`types.Tool`) в Gemini SDK для диалогового движка:
    * `create_calendar_event(title: str, date: str, start_time: str, end_time: str, description: str)` — запись события через `GoogleCalendarClient`.
    * `create_reminder(text: str, due_date: str, target: str, category: str)` — запись строки в таблицу `reminders`.
    * `draft_email_reply(email_id: int, reply_text: str)` — подготовка черновика в таблице `email_drafts`.
  - Механизм обработки вызова инструмента: вызов реального API бэкенда и передача результата `function_response` обратно в модель для формирования финального ответа.

- **`ACT-02` (Защита от галлюцинаций в системном промпте):**
  - Внедрение строгого правила в промпт `secretary`:
    * *«КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО утверждать, что событие внесено в календарь, создано напоминание или отправлено письмо, если в рамках текущего хода диалога не был успешно вызван соответствующий инструмент и не получен tool_result от системы»*.
  - Если информации недостаточно (например, не указано время дедлайна), ассистент обязан задать уточняющий вопрос пользователю, а не имитировать выполнение.

- **`ACT-03` (Интерактивные карточки подтверждения — HITL Guardrail):**
  - Перед созданием внешних событий в календаре или изменением критических данных ассистент формирует интерактивную карточку в Telegram с инлайн-кнопками:
    * `[📅 Записать в календарь: 10.10 18:30]`
    * `[⏰ Создать напоминание]`
    * `[❌ Отмена]`
  - Действие совершается только после явного нажатия кнопки владельцем (Human-in-the-Loop).

- **`ACT-04` (Специализированные интенты планирования в FastIntentRouter):**
  - Выделение специализированных категорий намерений: `calendar_schedule`, `create_reminder`, `draft_reply`.
  - Прямая маршрутизация таких запросов в целевые сценарии с извлечением сущностей (NER: даты, время, адресаты, темы) без прогона через общий свободный диалог.

## 🎨 Инициатива 5: Пересмотр интерфейса взаимодействия, динамические команды и аудит качества сервиса (`BOT-UXQ`)

**Цель:** Трансформация интерфейса взаимодействия с Telegram-ботом от статического монолитного списка команд к гибкой, контекстно-зависимой среде. Динамический рост меню команд при подключении новых сервисов, прямой пользовательский контроль над алиасами и названиями, а также системное улучшение качества продукта во всех аспектах (надежность, задержки, когнитивная эргономика).

### Требования:
- **`UXQ-01` (Динамическое меню команд и модульный реестр — Dynamic Bot Menu):**
  - Отказ от захардкоженного списка команд в пользу модульного реестра коннекторов и сервисов:
    * При подключении нового коннектора (LMS, AADHk, CalDAV, почта) бот автоматически регистрирует соответствующие команды в Telegram Bot API через `bot.set_my_commands()` со scope `BotCommandScopeChat(chat_id)`.
    * При отключении сервиса нерелевантные команды мгновенно исчезают из меню подсказок Telegram.
  - Поддержка многоуровневого меню (категории: 🎓 Академические, ⏱️ Табель, 📬 Почта, ⚙️ Настройки).

- **`UXQ-02` (Прямой контроль пользователя за командами и алиасами — Declarative Command Registry):**
  - Декларативное управление списком команд через `config/persona.yaml` или базу SQLite:
    * Пользователь может переименовывать команды (например, заменить `/timesheet` на удобное `/часы`).
    * Настройка персональных псевдонимов (aliases) для русскоязычного и англоязычного ввода.
    * Возможность скрыть неиспользуемые или редкие команды без отключения самого функционала.
  - Административное управление прямо из диалога: *«Переименуй команду /timesheet в /часы»*, *«Скрой команды LMS на время каникул»*.

- **`UXQ-03` (Контекстно-ориентированный интерфейс — Context-First UI & Quick Replies):**
  - Переход от необходимости ручного набора слэш-команд к динамическим контекстным клавиатурам (Reply Keyboard / Quick Actions):
    * Утренний блок (07:00–12:00): кнопки быстрого доступа `[🌅 Брифинг дня]`, `[📅 Расписание пар]`, `[📬 Срочная почта]`.
    * Рабочий блок (12:00–19:00): `[⏱️ Баланс часов]`, `[📝 Задачи и дедлайны]`, `[🎓 Отчеты LMS]`.
    * Вечерний блок (19:00–23:00): `[🌙 Вечерний дайджест]`, `[📅 Планы на завтра]`.
  - Минимизация текстового ввода: карточки действий с готовыми вариантами реакций в один клик.

- **`UXQ-04` (Системный аудит точек роста качества продукта — Product Quality Growth Areas):**
  - **1. Надежность и прозрачность (Observability & Health Heartbeat):**
    * Введение проактивного мониторинга сессий: если сессия LMS устарела или почтовый IMAP-сервер временно недоступен, бот отправляет ненавязчивое системное предупреждение с кнопкой `[🔄 Обновить токен]` вместо скрытого падения.
    * Механизм мгновенной обратной связи: инлайн-кнопки оценки ответа секретаря (👍 / 👎) для сбора телеметрии и дообучения промптов на проблемных кейсах.
  - **2. Скорость и минимизация задержек (Latency & Edge Caching):**
    * Семантическое кэширование детерминированных ответов (расписание на сегодня, статус табеля): отдача ответа за < 250 мс из SQLite без сетевого обращения к LLM.
    * Прогрев контекста перед утренним брифингом и вечерним дайджестом.
  - **3. Когнитивная эргономика и адаптивный стиль ответов:**
    * Режим компактного вывода (Mobile-First): автоматическое сокращение многословных списков до компактных карточек при просмотре со смартфона.
    * Интеллектуальный фильтр срочности (Urgency Scoring): разметка входящих писем и сообщений по степени критичности с мгновенным пуш-уведомлением только для срочных распоряжений руководства.

## 🧠 Инициатива 6: Платформа динамических специализированных субагентов и семантическая оркестрация (`SPEC-AGENTS`)

**Цель:** Создание модульной платформы субагентов-экспертов с изолированными базами знаний, замороженными контекстами и выделенными разделами памяти. Интеллектуальная маршрутизация задач на основе семантического анализа запросов пользователя с поддержкой паттернов делегирования (Supervisor Tool Use) и прямой передачи управления (Thread Handoff).

### Требования:
- **`SUB-01` (Изолированная архитектура субагента — 4-компонентная капсула):**
  - Каждый специализированный субагент формируется как изолированная капсула (Subagent Capsule):
    1. **Замороженный контекст (Frozen Context):** Неизменяемый системный промпт с четкой ролью, компетенциями, ограничениями, профессиональным тоном и запретами на выход за границы экспертизы. Защита от дрейфа инструкций и когнитивной перегрузки.
    2. **База знаний (Domain Knowledge Base):** Индексированные первоисточники, оглавления (TOC), нормативные документы, отраслевые терминологические словари и онтологии.
    3. **Выделенная файловая папка (Storage Sandbox):** Локальная директория в файловой системе (`data/subagents/<slug>/`) с учебниками, стандартами, шаблонами, PDF и расчетными материалами.
    4. **Раздел памяти в БД (Database Memory Partition):** Изолированное пространство таблиц SQLite (`subagent_qa_memory`, `subagent_facts`, `subagent_artifacts` с внешним ключом `subagent_id`), исключающее загрязнение оперативной памяти других агентов.

- **`SUB-02` (Семантический анализ намерений и интеллектуальный роутер — Semantic Intent Router):**
  - Двухуровневый семантический диспетчер запросов пользователя:
    * **Уровень 1 (Быстрый синтаксический фильтр):** Распознавание явных триггеров и обращений (`@методист`, `@тидекс`, `/methodist`, ключевые слова).
    * **Уровень 2 (Семантический эмбеддинг-анализ):** Анализ свободного текста пользователя нейросетевым роутером (или векторным сходством с профилями компетенций субагентов) для определения скрытого намерения.
    * **Оценка уверенности (Confidence Scoring):** Если запрос узкопрофильный (например, *«какой ГОСТ для оформления списка литературы»*), скоринг направляет его агенту-методисту; если комплексный — выделяет главного и консультирующего агента.

- **`SUB-03` (Паттерны оркестрации: Tool Delegation vs Thread Handoff):**
  - **Паттерн A: Supervisor / Tool Delegation (по умолчанию):**
    * Личный секретарь остается единой точкой входа для пользователя.
    * При распознавании специфического вопроса секретарь не переключает контекст чата, а вызывает специализированного субагента как инструмент (`tool_call`), получает экспертную выжимку и гармонично встраивает её в общий ответ.
  - **Паттерн B: Thread Handoff (прямая передача управления):**
    * При длительной исследовательской или проектной работе (например, сессия методической разработки РПД или решение оптических задач «Тидекс») управление диалогом передается напрямую субагенту.
    * В интерфейсе чата меняется заголовок/плашка (например, `🎓 В режиме: Агент-Методист`).
    * Возврат к общему секретарю в любой момент по команде (`/exit`, `/secretary`, `хватит`, `к секретарю`).

- **`SUB-04` (Декларативный реестр и динамический жизненный цикл субагентов):**
  - Создание новых субагентов без правки ядра через декларативные файлы конфигурации (`config/subagents/<slug>.yaml`):
    * Идентификатор, отображаемое имя, иконка, краткое описание компетенций.
    * Ссылка на папку документов и модель LLM по умолчанию.
    * Политика безопасности (Workspace isolation: `academic`, `corporate`, `personal`) с соблюдением требований NDA и изоляции коммерческой тайны.
  - Динамическое появление субагента в меню команд бота, списках задач и веб-панелях Antigravity Studio.

- **`SUB-05` (Непрерывное дообучение субагента в диалоге — In-Chat Learning):**
  - Механизм пополнения знаний конкретного специалиста прямо из чата:
    * Команда добавления правила: *«@методист, запомни: с 2026 года на титульном листе обязательна подпись научрука»*.
    * Загрузка документов в чат (PDF, docx) с целевым тегом: автоматическое сохранение в папку субагента, нарезка на чанки (Chunking) и индексация (FTS5 / Vector Store).

## 🎛️ Инициатива 7: Сквозная динамическая кастомизация алиасов/кнопок и интерактивный конструктор шорткатов (`CHAT-BUILDER` / Issue #44)

**Цель:** Предоставление пользователю полного гибкого контроля над элементами взаимодействия по всему чату секретаря: не только меню команд верхнего уровня, но и экранными Reply-кнопками, инлайн-клавиатурами карточек, а также интерактивный диалоговый конструктор для создания собственных шорткатов и макрокоманд по запросу.

### Требования:
- **`BLD-01` (Сквозная динамическая настройка кнопок и алиасов по всем сценариям секретаря):**
  - Универсальный декларативный слой для всех кнопок чата (Reply-клавиатуры, инлайн-кнопки под карточками, быстрые подсказки).
  - Возможность для пользователя переопределять текст, эмодзи и действие любой кнопки во всех сценариях (расписание, табель, почта, задачи, методист, вечерний дайджест).
  - Хранение пользовательских оверрайдов кнопок в SQLite (`bot_button_customizations`) с возможностью быстрого сброса на системные значения по умолчанию.

- **`BLD-02` (Интерактивный конструктор алиасов и кнопок по запросу в диалоге):**
  - Пошаговый диалоговый мастер (On-Demand Builder Flow), запускаемый по естественному запросу пользователя (*«Хочу создать новую кнопку»*, *«Создай шорткат»*, *«Собери кнопку для отчета»*):
    * Шаг 1: Выбор типа действия (вызов встроенной команды, запуск регулярного сценария или заготовленный текстовый промпт к секретарю).
    * Шаг 2: Ввод пользовательского названия кнопки / псевдонима и выбор иконки/эмодзи.
    * Шаг 3: Назначение расположения: привязка к экранной клавиатуре (Reply), быстрому алиасу в чате или в системное меню Telegram.
    * Шаг 4: Тестовое выполнение и мгновенное сохранение в профиль пользователя без перезапуска сервера.

- **`BLD-03` (Пользовательская компоновка клавиатур — Keyboard Layout Builder):**
  - Диалоговое управление структурой экранных Reply-клавиатур:
    * Группировка кнопок по строкам (сетка 2x2, 3x1 и т.д.).
    * Создание персональных пресетов под контексты (например, пресет *«Сессия»*, пресет *«Научная конференция»*, пресет *«Командировка»*).
    * Переключение активного пресета одной командой или по расписанию.

- **`BLD-04` (Параметризованные макро-алиасы):**
  - Поддержка шорткатов с автоматической подстановкой параметров (например, *«алиас вчера как timesheet yesterday»*, *«алиас лабы_физика как lms filter subject=физика»*).
  - Быстрый синтаксический разбор в FastIntentRouter с извлечением аргументов без задержек LLM.
