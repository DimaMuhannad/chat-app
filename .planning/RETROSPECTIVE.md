# Project Retrospective

*Живой документ: обновляется после каждого цикла (milestone).*

## Milestone: v2.0 — Универсальная платформа

**Shipped:** 2026-10-09 (override closeout)
**Phases:** 9 | **Plans:** 44 (43 выполнено, 09-03 перенесён) | **Commits:** ~199 chat-app, ~102 assistant-core с 2026-09-30

### What Was Built
- Локальный гейт качества `scripts/gate.py`: оба pytest, import-linter, security_shield, контроль дрейфа персоны и неизменности боевой БД.
- Порты и домен assistant-core, внутрипроцессный EventBus, конструкторная инъекция.
- Персона как данные: `persona.yaml`, таблицы персон, промпты в Jinja2 с побайтовыми эталонами, white-label UI.
- `assistant-shared`: владелец схемы БД (миграции, WAL) и единая библиотека безопасности.
- HITL-примитив `pending_confirmations`, Air-Gap NDA-почты, Zero-Trust scopes, ключи Gemini по персоне.
- Tool Calling секретаря с HITL-карточками; динамическое меню бота и алиасы.

### What Worked
- Гейт и тесты, закоммиченные до рефакторинга (характеризационные тесты, эталоны промптов, NDA-чек-лист), позволили переносить профиль в данные без регрессий.
- Решения владельца, зафиксированные заранее (W1–W10), закрывали спорные вопросы до планирования.
- Код-ревью фазы 4 нашло 7 критичных проблем безопасности (fail-open shield, обход NDA-remote), которые тесты не ловили.

### What Was Inefficient
- Фазы 4–9 закрывались без VERIFICATION.md; SUMMARY 06-01..06-04 не были записаны — пришлось восстанавливать по коммитам.
- ROADMAP и STATE расходились с реальностью (фазы 4–7 не отмечены, фаза 9 отсутствовала в ROADMAP).
- Компоненты фаз 5 и 7 протестированы юнит-тестами, но не подключены к рантайму (web HITL → Telegram, GitEvaluator) — выявлено только интеграционной проверкой при аудите.
- Один `.planning/` на два репозитория связывал разработку сервисов и раздувал гейт.

### Patterns Established
- Тесты-ловушки до правки, затем рефакторинг; baseline хардкода, который может только сокращаться.
- Security-логика только ужесточается (fail-closed); HITL для любого необратимого действия.
- Рутина — агентам agy только через изолирующую обёртку; в «клетке» нет истории git, задачи по коммитам Claude делает сам.

### Key Lessons
1. Фаза не считается закрытой без VERIFICATION.md и проверки «вызывается ли это из рантайма», а не только «есть ли тест».
2. SUMMARY пишется в том же прогоне, что и код; иначе планирование теряет связь с историей.
3. Отдельный GSD-проект на каждый независимо развиваемый сервис.

### Cost Observations
- Model mix: оркестрация Opus; ревью, исправления и интеграционная проверка — Sonnet-субагенты; чтение — попытка agy (неуспешна для git-истории).
- Notable: интеграционная проверка (~77k токенов) нашла два разрыва, пропущенных 9 фазами юнит-тестов.
