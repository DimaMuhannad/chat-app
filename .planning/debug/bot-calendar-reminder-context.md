# Debug Session: Отсутствие исполнительного контура (Tool Calling) в диалоге секретаря

## Current Focus
- hypothesis: "SecretaryDialogEngine генерирует текст без инструментального контура (Function Calling) и не имеет обработчиков для создания событий в Google Calendar или записей в SQLite reminders. Модель галлюцинирует исполнение, а FastIntentRouter маршрутизирует запрос как общий диалог 'secretary'."
- next_action: "Зафиксировать системные архитектурные требования в .planning/BACKLOG.md (Инициатива TOOL-ACT: Tool Calling & Real Actions) для последующей реализации в отдельной фазе."

## Evidence
- 2026-10-04T23:23:00Z: В `src/brain/secretary_dialog.py:698` вызов `client.aio.models.generate_content` передает только `contents=user_prompt` и `system_instruction`. Параметр `tools` отсутствует.
- 2026-10-04T23:23:30Z: В SQLite-базе `data/assistant.db` таблица `reminders` содержит только старые записи от 29.09.2026. Новых записей нет.
- 2026-10-04T23:23:30Z: В таблице `calendar_sync_records` новые записи по письму Новиковой отсутствуют (содержатся только синхронизированные пары ГУАП).
- 2026-10-04T23:25:39Z: Журнал `router_audit_log` зафиксировал `action_chosen = 'secretary'` с уверенностью 0.98 на запросы о создании напоминания и отметке в календаре.

## Eliminated
- Исключена гипотеза о сбое Google Calendar API: клиент календаря даже не вызывался, так как в коде диалога нет вызова `calendar_client.create_event`.
- Исключена гипотеза об ошибке прав доступа SQLite: база доступна на запись, но метод `add_reminder` из диалога не вызывается.

## Root Cause
`SecretaryDialogEngine` изначально проектировался как информационно-консультационный агент (RAG над расписанием, почтой, методическими материалами и табелем). В нем отсутствует исполнительный контур (Action Execution / Function Calling) для обратного воздействия на систему (Google Calendar, SQLite Reminders, Email Drafts). Модель в промпте получает указание действовать как личный секретарь и, пытаясь выполнить запрос пользователя, генерирует текстовое подтверждение ("задача внесена в календарь"), не имея технических средств для совершения этого действия.

## Proposed Systemic Fix (Backlog: TOOL-ACT)
1. Регистрация инструментов Gemini (`types.Tool`) в `SecretaryDialogEngine`:
   - `create_calendar_event(title, date, start_time, end_time, description)`
   - `create_reminder(text, due_date, target, category)`
   - `draft_email_reply(email_id, text)`
2. Обработка `function_calls` с вызовом реальных методов сервисов и возвратом `function_response` в модель.
3. Интерактивные карточки подтверждения (HITL Guardrail) перед совершением внешних записей.
4. Добавление правила в системный промпт: строгий запрет на рапортование о создании записей до получения подтверждающего `tool_result`.
